* 가장 먼저, 이번 달의 소중한 식비 예산을 설정하고 오늘 새로 산 식재료의 이름과 가격, 그리고 남은 유효기간(혹은 무게)을 기록하는 것으로 관리를 시작합니다. 그다음에는 입력한 정보를 바탕으로 이 재료가 내 전체 예산에서 어느 정도의 비중을 차지하는지 '식비 점유율'을 계산해 봅니다. 이렇게 계산된 점유율이 너무 높으면 '지출 주의' 경고를, 적절하면 '합리적 소비'라는 판정을 내려줍니다. 만약 가격도 저렴한데 영양가까지 높은 '갓성비' 재료를 샀다면 '알뜰 자취왕'이라는 특별한 칭호를 부여하여 동기부여를 해줄 것입니다. 나중에는 단순히 하나씩 기록하는 것이 아니라, 냉장고 속의 수많은 재료를 커다란 바구니(리스트)에 담아 유통기한 순으로 정렬하거나 전체 남은 예산을 실시간으로 조회할 수 있게 만들 것입니다. 최종적으로는 사용자가 메뉴판에서 번호를 눌러 기능을 선택하고, '자취 종료(로그아웃)'를 하기 전까지는 계속해서 식재료를 관리할 수 있는 완벽한 자취 보조 소프트웨어로 완성될 계획입니다.

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
* 이번 과제는 **[자취 라이프 매니저] 냉장고 관리 시스템 V1.0** 구현으로, 사용자로부터 식비 예산과 식재료 정보를 입력받아 리스트에 저장하고, 지출 금액과 예산 점유율을 계산하는 프로그램을 만드는 것입니다.
* `input()`으로 사용자 이름, 이번 달 식비 예산, 식재료 이름, 가격, 남은 유통기한, 영양 점수를 입력받아 리스트에 저장했습니다.
* 사용자로부터 식재료 정보를 입력받아 `apped()` 를 활용해 식재료 이름, 가격, 유통기한, 영양 점수를 각각 리스트에 저장했습니다. 이를 통해 여러 식재료 데이터를 개별 변수 대신 리스트로 관리할 수 있도록 구성했습니다.
* `sum()`, `len()`, `max()`, `sort()`, `insert()` 등을 활용하여 리스트 데이터를 조작하고, 총 지출 금액과 남은 예산, 식비 점유율을 계산했습니다.
* `if-elif-else` 조건문을 사용하여 지출 등급을 **알뜰 소비 / 적정 소비 / 과소비 주의**로 판정했습니다.
* `and`, `or`, `not` 논리 연산자와 중첩 조건문을 활용하여 예산과 영양 점수를 함께 고려한 **알뜰 자취왕** 특별 칭호를 부여했습니다.

    
### **🤖 AI 파트너십 과정**
1. **문제 1: 변수 이름 오타로 인해 없는 항목이라고 뜨는 문제**
    * **원인:** 리스트나 변수 이름을 선언할 때 사용한 이름과 출력 또는 계산할 때 사용한 이름이 서로 달라서 오류가 발생했습니다. 예를 들어 `food_prices`로 만든 리스트를 다른 줄에서 `food_price`처럼 잘못 입력하면 파이썬이 해당 변수를 찾지 못했습니다.
    * **해결:** 변수 이름을 한 줄씩 확인하면서 선언한 이름과 사용하는 이름을 모두 동일하게 수정했습니다. 이번 경험을 통해 변수 이름은 처음부터 의미 있게 정하고, 같은 이름을 끝까지 일관되게 사용하는 것이 중요하다는 것을 알게 되었습니다.

2. **문제 2: 필요한 코드 한 줄을 빠뜨려 실행 결과가 원하는 대로 나오지 않은 문제**
    * **원인:** 식재료 정보를 입력받은 뒤 리스트에 추가하는 `append()` 줄이나, 총 지출 금액을 누적하는 `total_price += price` 줄을 빠뜨려 계산 결과가 제대로 반영되지 않았습니다.
    * **해결:** 입력 → 리스트 저장 → 계산 → 출력 순서로 코드 흐름을 다시 확인하며 빠진 줄을 추가했습니다. 특히 반복문 안에서 입력받은 값이 리스트에 저장되고 있는지, 총 지출 금액에 누적되고 있는지 확인했습니다.

3. **문제 3: input으로 입력받은 숫자가 계산에 바로 사용되지 않는 문제**
    * **원인:** `input()`으로 입력받은 값은 기본적으로 문자열이기 때문에 가격이나 예산 계산에 바로 사용할 수 없었습니다.
    * **해결:** 예산과 가격은 `int()`, 영양 점수는 `float()`로 형변환하여 계산이 가능하도록 수정했습니다.

4. **문제 4: 조건문 결과가 예상과 다르게 출력되는 문제**
    * **원인:** `if`, `elif`, `else`의 순서를 잘못 배치하거나 조건 범위를 애매하게 작성하여 원하는 등급이 출력되지 않았습니다.
    * **해결:** 식비 점유율이 큰 경우부터 차례대로 검사하도록 조건문의 순서를 정리했습니다. 또한 `and`, `or`, `not` 연산자를 사용할 때 각각의 조건이 어떤 의미인지 확인하며 수정했습니다.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문) - 향후 작성 예정
### **✨3차 과제 업데이트 내용:**
* 이번 3차 과제에서는 기존 [자취 라이프 매니저] 냉장고 관리 시스템을 메뉴형 프로그램으로 확장하였다.
* 2차 과제에서는 식재료 정보를 입력받고 계산 결과를 출력한 뒤 프로그램이 종료되는 구조였지만, 3차 과제에서는 `while True` 무한 반복문을 사용하여 사용자가 원하는 기능을 계속 선택할 수 있도록 수정하였다.

* `calculate_budget_rate(total, budget)` 함수에서는 매개변수로 총 지출 금액과 예산을 전달받아 식비 점유율을 계산하고, 계산 결과를 `return`으로 반환하도록 구현하였다.
* `add_food()` 함수에서는 식재료를 새로 등록할 때마다 전체 지출 금액인 `total_price`가 누적되어야 하므로, `global` 키워드를 사용하여 전역변수 값을 함수 내부에서 수정할 수 있도록 하였다.
* `for`문을 이용하여 리스트에 저장된 식재료 이름, 가격, 유통기한, 영양 점수를 순서대로 출력하고, 유통기한이 3일 이하로 남은 식재료를 찾아 알려주는 기능을 추가하였다.
    
### **🤖 AI 파트너십 과정**

    * **적용 내용:** AI와 함께 3차 과제 파일의 요구사항을 확인하고, 기존 코드를 메뉴형 프로그램으로 확장하는 방향을 정하였다. `while True`를 사용하여 메인 메뉴가 반복 출력되도록 하고, 사용자가 종료 메뉴를 선택했을 때만 `break`로 프로그램이 끝나도록 설계하였다.
 2. **내용 2: 기존 기능의 함수 분리**
    * **프롬프트 요약:** "2차 과제에서 만든 식재료 입력, 예산 계산, 지출 등급 판정 기능을 3차 과제 조건에 맞게 함수로 나누려면 어떻게 해야 해?"
    * **적용 내용:** 기존 코드에 있던 식재료 등록, 전체 목록 출력, 식비 점유율 계산, 지출 등급 판정, 특별 칭호 확인, 유통기한 임박 식재료 확인 기능을 각각 함수로 분리하였다. 이를 통해 메인 코드에서는 메뉴 번호에 따라 함수를 호출하는 방식으로 구조를 단순화하였다.
 3. **내용 3: 매개변수, return, global 사용 위치 결정**
    * **프롬프트 요약:** "과제 조건에 매개변수, return, global을 한 번 이상 사용해야 한다고 되어 있는데 어느 부분에 넣는 게 자연스러울까?"
    * **적용 내용:** 식비 점유율 계산 기능을 `calculate_budget_rate(total, budget)` 함수로 분리하여 매개변수와 return을 사용하였다. 또한 식재료 등록 시 전체 지출 금액을 누적해야 하므로 `add_food()` 함수 안에서 `global total_price`를 사용하였다. 반면 `remaining_budget`, `budget_rate`는 함수가 실행될 때마다 새로 계산되는 값이므로 지역변수로 두는 것이 적절하다고 판단하였다.
    
### **🛠️ Troubleshooting & 기술 회고:**
 1. **문제 1: 기존 프로그램이 한 번 실행된 뒤 바로 종료되는 문제**
   * **원인:** 2차 과제 코드에서는 식재료 정보를 입력하고 결과를 출력한 뒤 프로그램이 바로 종료되는 구조였다. 따라서 사용자가 추가로 식재료를 등록하거나 다른 기능을 다시 선택할 수 없었다.
   * **해결:** `while True`를 사용하여 메인 메뉴가 계속 반복되도록 수정하였다. 사용자가 `0`번 종료 메뉴를 선택했을 때만 `break`로 반복문을 종료하도록 구현하여 메뉴형 프로그램 구조를 완성하였다.

 2. **문제 2: 함수로 분리한 뒤 `total_price` 값이 제대로 누적되지 않을 수 있는 문제**
   * **원인:** `total_price`는 프로그램 전체에서 사용되는 전역변수인데, `add_food()` 함수 내부에서 값을 변경하려면 함수 안에서 전역변수임을 명확히 알려주어야 했다.
   * **해결:** `add_food()` 함수 내부에 `global total_price`를 작성하여 식재료 가격이 입력될 때마다 전체 지출 금액이 정상적으로 누적되도록 수정하였다.

 3. **문제 3: 식비 점유율 계산식이 여러 기능에서 반복되는 문제**
   * **원인:** 식비 점유율은 예산 확인, 지출 등급 판정, 특별 칭호 확인 기능에서 모두 필요했기 때문에 같은 계산식을 여러 번 작성하면 코드가 길어지고 수정하기 어려워질 수 있었다.
   * **해결:** `calculate_budget_rate(total, budget)` 함수를 따로 만들어 총 지출 금액과 예산을 매개변수로 전달받고, 계산된 식비 점유율을 `return`으로 반환하도록 하였다. 이를 통해 같은 계산을 여러 메뉴에서 재사용할 수 있게 되었다.

 4. **문제 4: 등록된 식재료가 없을 때 목록 출력이나 유통기한 확인이 어색한 문제**
   * **원인:** 식재료 리스트가 비어 있는 상태에서 전체 목록 출력이나 유통기한 임박 확인 기능을 실행하면 출력할 데이터가 없었다.
   * **해결:** `len(food_names) == 0` 조건을 사용하여 등록된 식재료가 없는 경우에는 "아직 등록된 식재료가 없습니다."라는 안내 문구가 출력되도록 하였다.

 5. **문제 5: 전역변수와 지역변수의 역할 구분이 헷갈린 문제**
   * **원인:** `remaining_budget`, `budget_rate`도 여러 함수에서 사용되기 때문에 전역변수로 만들어야 하는지 고민하였다.
   * **해결:** `total_price`처럼 프로그램 전체에서 계속 유지되고 변경되는 값은 전역변수로 사용하고, `remaining_budget`과 `budget_rate`처럼 현재 상태를 바탕으로 잠시 계산하는 값은 각 함수 내부의 지역변수로 처리하였다. 이를 통해 전역변수와 지역변수의 역할을 구분할 수 있었다.

### **🛠️ Troubleshooting & 기술 회고:**

1. **문제 1: 기존 리스트 구조가 4차 과제의 이중 리스트 조건과 맞지 않았다.**

   * **원인:**
     기존 코드에서는 식재료 이름, 가격, 유통기한, 영양 점수를 각각 다른 리스트에 따로 저장했기 때문에 하나의 식재료 정보를 한 번에 관리하기 어려웠다.
   * **해결:**
     식재료 하나의 정보를 `[식재료 이름, 가격, 유통기한, 영양 점수]` 형태의 리스트로 묶고, 이를 `foods`라는 전체 리스트에 추가하는 이중 리스트 구조로 변경하였다.

2. **문제 2: 숫자 입력 위치에 문자를 입력하면 프로그램이 오류로 종료될 수 있었다.**

   * **원인:**
     `int()`나 `float()`으로 입력값을 변환할 때 숫자가 아닌 문자가 들어오면 `ValueError`가 발생하기 때문이다.
   * **해결:**
     숫자 입력을 처리하는 부분에 `try-except`를 적용하여 잘못된 값이 입력되면 안내 문구를 출력하고 다시 입력받도록 수정하였다.

3. **문제 3: 저장된 파일이 없는 상태에서 파일 불러오기를 실행하면 오류가 발생할 수 있었다.**

   * **원인:**
     `fridge_data.txt` 파일이 아직 생성되지 않은 상태에서 읽기 모드로 파일을 열려고 하면 `FileNotFoundError`가 발생하기 때문이다.
   * **해결:**
     파일 불러오기 함수에 `except FileNotFoundError`를 추가하여 저장된 파일이 없을 경우 사용자에게 안내 메시지를 출력하도록 하였다.
